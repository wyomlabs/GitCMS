**The short answer:** if you build websites in code, often with Claude Code, Codex, or Cursor, the best WordPress alternative is a code-first site with **GitCMS** as its admin. Your clients and marketers still get a place to edit and publish, every change can wait for review, and the site stays in your own repository. If nobody on the team writes code, pick **Webflow**. If the site runs WooCommerce or memberships, stay on WordPress.

This guide is for agencies, freelancers, and startups that build sites in code and hand them to people who don't. It ranks seven tools for that job. If that isn't you, skip to [when to stay on WordPress](#when-should-you-stay-on-wordpress) or [options outside this list](#not-building-in-code).

## How we ranked them

A disclosure first: I build GitCMS, so treat the ranking as an informed opinion, not a neutral review. What I can do is show exactly what it rewards. These are the four things that decide whether a WordPress replacement works for a team that builds in code:

1. **Clients edit without Git or a developer.** The reason teams stayed on WordPress was wp-admin. A replacement has to give non-technical people a place to change copy and publish posts.
2. **Review before publish.** Clients, teammates, and now AI agents all change the site. A change should be able to wait for approval before it goes live.
3. **The code and content stay yours.** The site and its content live in your repository, so you can change hosts, tools, or agencies without a migration.
4. **It works with agents.** Coding agents build and change the site; content agents like ChatGPT and Claude draft posts and updates. Both should fit the workflow.

## The best WordPress alternatives, ranked

GitCMS is the CMS for code-first and AI-built websites. It gives your team, your clients, and AI agents one safe place to edit, review, and publish website changes, while everything stays in your site's repository.

It's the closest thing to wp-admin for a site that's code. Your coding agent builds the site and runs `create-gitcms` to configure it. Clients sign in with Google, edit pages and posts in a [visual editor](/features/visual-editor/), and change menus and footers through forms, without a GitHub account. With [review before publish](/features/editorial-workflow/), their changes and your AI agents' drafts wait on a content board until someone approves them.

<Strengths>

- Clients edit content, never components, so they can't break the design.
- Review before publish on every site, with inline comments and approvals.

- Every save is a Git commit, so there's no database or sync layer to run.

## Not building in code?

The ranking above assumes someone on the team builds the site in code, or wants to with a coding agent. If not:

## When should you stay on WordPress?

Stay if any of these describe your site:

- **E-commerce runs on WooCommerce.** Products, checkout, inventory, and taxes are a whole application. Moving them is a re-platforming project, not a CMS swap.
- **Memberships, courses, or gated content.** Logins, payments, and access rules are dynamic features WordPress plugins handle well. A static site needs a separate service for each.
- **Workflows depend on specific plugins.** Booking, forms feeding a CRM, LMS, multilingual. List each one and price its replacement before planning a migration.
- **No developer, and the team designs pages visually.** If the people running the site build new layouts themselves, WordPress with a page builder (or Webflow or Framer) suits them better than a code-first site.
- **It works, and it's maintained.** A patched, fast WordPress site with a happy client doesn't need rescuing.

## How do you move a WordPress site to code?

Here's the practical path. Each step has a prompt you can hand to Claude Code, Codex, or Cursor.

1. **Export the content.** In the WordPress admin, go to Tools → Export and download everything as a WXR (XML) file. Download the media library too, or let the agent fetch images from the live site.
2. **Convert posts to Markdown.** Turn the export into one Markdown file per post, with title, date, slug, categories, featured image, and meta description in frontmatter. Use the [convert WordPress posts to Markdown prompt](/prompts/convert-wordpress-posts-to-markdown/), and match field names to your framework's content schema first.
3. **Rebuild the site with a coding agent.** Recreate the design and templates in Astro (or your framework), keep every existing URL, and generate redirects for any that must change. The [migrate WordPress to Astro prompt](/prompts/migrate-wordpress-to-astro/) spells out the parts that matter for search: URLs, redirects, metadata, and the sitemap.
4. **Make the site client-editable.** Agents tend to write copy straight into components. Move headlines, opening hours, prices, and contact details into content files so a CMS can edit them safely. Use the [make a site client-editable prompt](/prompts/make-site-client-editable/).
5. **Give the client back an admin.** Connect the repository to a Git-based CMS, invite the client to their site only, and decide whether changes publish directly or wait for review. The [Claude Code client handoff guide](/blog/hand-off-claude-code-website-to-client/) walks through the whole handoff.

Before you switch DNS, check every template, a sample of posts, and the redirects against the old site's URLs. Lost rankings after a migration usually come from broken URLs, not the new framework.

## FAQ

### What is the best WordPress alternative for agencies?

For agencies that build client sites in code, a code-first site with GitCMS as its admin. Clients edit and publish without Git, changes can wait for review, and the agency keeps the code. For agencies that design visually without code, Webflow.

### Is there a WordPress alternative without PHP or a database to maintain?

Yes. A static or pre-rendered site built with Astro, Next.js, Hugo, or Eleventy serves files from a CDN, so there's no PHP runtime or MySQL database to patch. A Git-based CMS like GitCMS, CloudCannon, or TinaCMS edits the content files in the repository.

### Can clients still edit a site built with Claude Code?

Yes, once the editable text lives in content files instead of components. A Git-based CMS then gives clients a visual editor on top of those files. GitCMS lets them sign in with Google, so they don't need a GitHub account.

### What's the cheapest way to replace WordPress?

For a marketing site, static hosting on a free tier of Vercel, Netlify, Cloudflare, or GitHub Pages, plus a Git-based CMS. There's no managed WordPress hosting or premium plugins to pay for. The calculator above compares the yearly totals.
