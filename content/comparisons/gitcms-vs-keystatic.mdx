Keystatic is one of the best-designed tools in the Git-based CMS space. Built by Thinkmill (the team behind KeystoneJS) and MIT-licensed, it makes Markdown, JSON, and YAML content in your codebase editable through an admin UI, with a TypeScript schema API and a Reader API. It edits your local filesystem during development and GitHub in production. No database, no content API.

GitCMS is the CMS for code-first and AI-built websites. It shares Keystatic's foundation (content as files in a repo, Git as the backend) but it is built for different people. Keystatic is developer-first: you define the schema in TypeScript and add the admin to your app. GitCMS is a hosted admin you connect to an existing repository, for the clients, marketers, and AI agents who run the site after launch.

Both are honest tools. The question is whether you want a CMS library inside your codebase, or an admin your team, clients, and agents use without touching it.

## What changed in 2026

Git-based CMSs started as tools for developers who already preferred static sites and Markdown. That audience still exists. But a much larger group now arrives at the same architecture by a different road: they had Claude Code, Codex, or Cursor build the site, and the site naturally lives in Git.

That group doesn't mainly need a nicer way for developers to edit Markdown. They need **Day Two**: a way for clients and marketers to run the site without Git, and a way to review what AI agents change before it goes live. Keystatic is an excellent developer-configured CMS you add to your app. GitCMS is built around that Day Two workflow: a hosted admin you connect to an existing GitHub repo, review before publish, and bring-your-own agents through MCP.

## Same foundation, different audience

Both Keystatic and GitCMS store content as files in a Git repo. Both avoid databases and content APIs. The content is portable in both cases: plain files you can move anywhere.

Where they diverge is who they are built for.

### Keystatic: built for developers

Keystatic gives developers a TypeScript API to define content schemas (collections and singletons), a Reader API to query content at build time, and an admin panel that renders from those definitions. The developer assembles the editing experience in code.

This is a good model when developers own the content architecture. Keystatic's local mode is excellent: during development, edits land straight on your filesystem. In GitHub mode, editors work on branches through a branch picker and need GitHub accounts with write access, unless you use Keystatic Cloud, which lets team members edit without one.

### GitCMS: built for the people who run the site

GitCMS needs nothing added to the site's code. A coding agent like Claude Code, Codex, or Cursor runs `create-gitcms`, detects your collections, and writes the `.gitcms/` configuration. One repository can hold several websites, each configured separately.

Editors get a **document-style visual editor**: slash commands, drag-and-drop blocks, tables, callouts, and frontmatter as typed form fields. Site data such as menus, footers, and team lists is edited as forms, and only changed values are written back. Invited editors sign in with Google, without a GitHub account, and see only the sites they have access to.

## Review and agents: the Day Two gap

Keystatic gives you branches. GitCMS gives you a review workflow around them:

- **Content board.** Content tasks move through Ideas, Draft, Review, and Published. With review before publish, drafts stay off the live site until approved.
- **Reviews in the editor.** Inline comments beside the text, changes marked inline, approve or request changes, optional required approval.
- **Preview deployments (beta).** Reviewers see drafts on Vercel- or Netlify-style preview builds.
- **Change Requests (beta).** Clients pin feedback on the live website. It arrives as a GitHub issue, and "Copy prompt" hands it to your coding agent.

Coding agents can edit Keystatic's files directly, and that works with GitCMS too. GitCMS adds a structured path for **content agents**: ChatGPT, Claude, and other MCP clients read and edit entries and site data, draft inside content tasks, and submit for review. A person publishes. Keystatic has no MCP server or AI integration layer.

## Content as code

Both tools deliver the core content-as-code benefits:

- **`grep` works.** Search your entire content library with standard dev tools.
- **`git log` works.** Every content change has a commit, an author, a timestamp, and a diff.
- **`git blame` works.** Trace any sentence to the person or agent that wrote it.
- **Deploys are atomic.** Content and code ship together.

This is shared ground, and why both are easier to live with than a database-backed CMS.

Keystatic's core is free, and Keystatic Cloud is free for small teams. For developer-led teams comfortable configuring the CMS in TypeScript, the cost is close to zero.

GitCMS is a paid hosted product. You're paying for the client-facing editor, review workflow, and MCP access; see pricing above.

## Where Keystatic is genuinely better

Keystatic is the stronger choice when **developers want full control over the CMS**.

- **TypeScript schema API.** Define content models in code with a rich, typed API.
- **Local mode.** Content edits land on your filesystem during development, no network needed.
- **Reader API.** Typed, programmatic content access at build time.
- **Free and open source**, with an inexpensive optional cloud.
- **Thinkmill pedigree.** A well-built tool from a team that has shipped CMSs for years.

A note on pace: Keystatic's releases have slowed. The last `@keystatic/core` release was 0.6.9 in August 2026, and the repository's last commit was in early October. It works well today; check the repo before betting a large project on new features.

## Where GitCMS is better

GitCMS is better when **the people running the site aren't the developers who built it**.

Keystatic is built for developers to configure. GitCMS is built for clients, marketers, and agents to use:

- **Nothing to add to your app.** A coding agent runs `create-gitcms`, including for repos with several sites.
- **Review as the product.** Content board, reviews in the editor, preview deployments (beta).
- **Client access.** Google sign-in, per-site access, and Change Requests (beta) on the live site.
- **MCP agents** that draft for review instead of committing directly.

<Tradeoffs>
  <p>Choosing GitCMS over Keystatic is a real tradeoff:</p>
  <ul>
    <li>Keystatic's TypeScript schema API gives developers deeper control over the CMS configuration.</li>
    <li>Keystatic's local mode is excellent. GitCMS works against GitHub, not your filesystem.</li>
    <li>Keystatic is free and open source with an optional cloud. GitCMS is a paid hosted product.</li>
    <li>If your team is all developers comfortable with an admin panel, Keystatic may be all you need.</li>
  </ul>
  <p>For agencies and teams handing a site to non-technical editors, and letting AI agents propose changes, these tradeoffs are usually worth it.</p>

## Decision by use case

**Developer-configured CMS with a TypeScript schema API:** Keystatic is the better fit.

**Local-first development with programmatic content access:** Keystatic is the better fit.

**Developer-only team, free tooling preferred:** Keystatic works great.

**Non-technical editors running a code-first website:** GitCMS is the better fit.

**Agency handing a Claude Code or Astro site to a client:** GitCMS is the better fit.

**AI agents drafting website changes with human review before publishing:** GitCMS is the better fit.
