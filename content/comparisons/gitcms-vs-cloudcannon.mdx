CloudCannon is the most established commercial Git-based CMS. It has been around since 2013, supports a wide range of static site generators (Astro, Eleventy, Hugo, Jekyll, Next.js, Nuxt, SvelteKit, and others), connects to GitHub, GitLab, or Bitbucket, and offers visual editing with live preview, component-based page building, and hosting. It is a full platform: Git-backed content management with builds, hosting, and publishing in one product.

GitCMS is the CMS for code-first and AI-built websites. It does not host your site or run your builds. It connects to the GitHub repository behind a site you or your coding agent already built, and gives your team, your clients, and AI agents one safe place to edit, review, and publish changes. The content stays in your repo and deploys wherever you already deploy.

Both store content in Git, and both now talk about AI. The real difference is who sits at the center: CloudCannon is built around developers setting up a visual editing platform for their team. GitCMS is built around the people and agents who run a site after launch.

## Platform vs admin

This is the fundamental difference.

### CloudCannon: a CMS platform

CloudCannon is a full stack. You connect your Git repo, CloudCannon builds your site, hosts it, and gives editors a visual interface to update content. It handles:

- **Builds and hosting**: CloudCannon builds your site on every push and serves it
- **Visual editing**: editors see the rendered site and edit content in place, with a live preview they can share
- **Page building**: developers define components, and editors assemble pages from them
- **Team collaboration**: custom permission groups, content scheduling, and branching workflows on higher plans

This is convenient. One platform handles everything from editing to deployment. For teams that want a single vendor for their content workflow and hosting, CloudCannon simplifies the operational model.

The tradeoff: content management is coupled to a hosting platform. CloudCannon's build output is static files, so you can deploy elsewhere, but the product is designed around running the whole pipeline.

### GitCMS: the admin for a site that already exists

GitCMS makes the content in your repo easy to write, review, and publish. It does not build or host your site. Your existing deployment on Vercel, Netlify, Cloudflare, or GitHub Pages stays exactly as it is.

Setup is built for code-first sites. A coding agent like Claude Code, Codex, or Cursor runs `create-gitcms` in the repo, detects your collections, and writes the `.gitcms/` configuration. One repository can hold several websites, each configured separately.

## The editor question

CloudCannon's visual editor lets editors work directly on the rendered site. They see the page as it will look, click on elements, edit in place, and add sections from components. This is strong for pages where layout matters: landing pages, component-heavy marketing pages.

GitCMS gives you a **document-style visual editor**. It is built for writing: slash commands, drag-and-drop blocks, tables, callouts, and frontmatter as typed form fields. Menus, footers, team lists, and theme settings in JSON, YAML, or TOML files are edited as forms, and only changed values are written back.

For text-heavy content, a dedicated writing editor is often better than editing on the rendered page. For layout-heavy content, CloudCannon's visual editing has the edge.

## Review: the Day Two question

Most CloudCannon features answer "how does my team edit this site?" GitCMS answers a narrower question that matters more now that agents build sites: **how do changes from clients, marketers, and AI agents get reviewed before they go live?**

- **Content board.** Work moves through Ideas, Draft, Review, and Published. With review before publish, drafts stay off the live site until someone approves them.
- **Reviews in the editor.** Reviewers comment beside the text, see changes marked inline, and approve or request changes.
- **Preview deployments (beta).** GitCMS finds Vercel- or Netlify-style preview builds, so reviewers see drafts on the real site before publishing.
- **Change Requests (beta).** Clients click an element on the live website and pin feedback. It reaches the developer as a GitHub issue, and "Copy prompt" hands it to Claude Code, Codex, or Cursor.

CloudCannon has branching workflows on its Team plan. GitCMS makes review the default way a site is run.

## AI agents and MCP

CloudCannon's AI pitch is aimed at coding agents. It points out, correctly, that plain files in Git are what Cursor, Claude Code, and Copilot work best with, and it publishes open-source agent skills that migrate Astro projects onto CloudCannon. Agents propose changes on a branch and go through review like any pull request.

GitCMS covers coding agents too, since your content is still plain files in your repo. It adds a path for **content agents**. ChatGPT, Claude, and other MCP clients connect to GitCMS, read and edit entries and site data, draft inside content tasks, and submit for review. A person publishes. You bring the agent you already use; GitCMS sells no AI credits.

## Content as code

Both tools deliver the content-as-code benefits:

- **`grep` works.** Search your entire content library with standard dev tools.
- **`git log` works.** Every content change has a commit, an author, a timestamp, and a diff.
- **`git blame` works.** Trace any sentence to the person or agent that wrote it.
- **Deploys are atomic.** Content and code ship together.

This is shared ground. Both are better than database-backed CMSs for content portability and developer workflow.

CloudCannon includes hosting and builds in the price, so the comparison is not apples-to-apples. If you need a hosting platform plus a CMS, CloudCannon's Standard plan covers both. If you already host on Vercel, Netlify, or Cloudflare, part of what you pay for is hosting you already have.

## Where CloudCannon is genuinely better

CloudCannon is the stronger choice when you want **a full CMS platform with hosting and on-page visual editing**.

- **One platform.** Content editing, builds, hosting, and publishing from one vendor.
- **On-page editing and page building.** Editors click the rendered page, edit in place, and assemble new pages from components. GitCMS edits content, not layout.
- **GitLab and Bitbucket.** CloudCannon connects to all three major Git providers. GitCMS is GitHub-only.
- **Scheduling and fine-grained permissions.** Content scheduling and custom permission groups that GitCMS does not offer.
- **Track record.** More than a decade of production use with Hugo, Jekyll, and Eleventy sites.

If your editors build pages, not just edit them, CloudCannon is a mature platform that does that well.

## Where GitCMS is better

GitCMS is better when **the site already exists and deploys, and what you need is a way for everyone else to run it**.

Most code-first sites, especially ones built with Claude Code, Codex, or Cursor, already deploy through Vercel, Netlify, Cloudflare, or GitHub Actions. The build-and-host problem is solved. What's missing is a safe way for clients, marketers, and agents to change the site without a developer in the loop.

- **Onboarding by your coding agent.** `create-gitcms` writes the config; there's no platform to migrate onto.
- **Editors without GitHub accounts.** Invited editors sign in with Google and get access only to their site.
- **Review as the default.** Content board, reviews in the editor, and preview deployments (beta) before anything goes live.
- **Agents that propose, people who publish.** Bring ChatGPT, Claude, or any MCP client; no AI credits to buy.
- **Client feedback on the live site.** Change Requests (beta) turn a pinned comment into a GitHub issue a coding agent can pick up.

## Decision by use case

**Full CMS platform with hosting, builds, and on-page visual editing:** CloudCannon is the better fit.

**Repositories on GitLab or Bitbucket:** CloudCannon is the better fit.

**Marketers assembling new pages from components:** CloudCannon is the better fit.

**Agency handing a Claude Code or Astro site to a client:** GitCMS is the better fit.

**AI agents drafting website changes with human review before publishing:** GitCMS is the better fit.

**Team that already deploys on Vercel or Netlify and needs the admin:** GitCMS is the better fit.
