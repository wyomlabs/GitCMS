Sveltia CMS is what Decap CMS users hoped Decap would become. It is a successor to Netlify and Decap CMS that keeps compatibility with existing configurations, but with a modern UI, much better performance, first-class internationalization, and fixes for 390 issues reported against Decap. Built with Svelte, it runs as a small single-page app served from a CDN. It's MIT-licensed, ships releases several times a week, and expects its 1.0 release in late 2026.

If you're on Decap CMS today and want a better experience without changing your setup, Sveltia CMS is probably the shortest path to an upgrade.

GitCMS solves a different problem. It doesn't try to be a better Decap. Decap and Sveltia are admin panels a developer adds to a site; GitCMS is built for the people and agents who run the site after launch, with a visual editor for clients and marketers, review before publish, and AI agents through MCP. The content model is the same (files in Git); who the tool is for is not.

## What changed in 2026

Git-based CMSs started as tools for developers who already preferred static sites and Markdown. That audience still exists. But a much larger group now arrives at the same architecture by a different road: they had Claude Code, Codex, or Cursor build the site, and the site naturally lives in Git.

That group doesn't mainly need a nicer way for developers to edit Markdown. They need **Day Two**: a way for clients and marketers to run the site without Git, and a way to review what AI agents change before it goes live. Sveltia CMS is a fast, free, modern successor to Decap. GitCMS is built around that Day Two workflow: a hosted admin you connect to an existing GitHub repo, review before publish, and bring-your-own agents through MCP.

## Two approaches to improving on Decap

Decap CMS proved that Markdown in Git works as a CMS. Sveltia CMS and GitCMS both respond to what came after, in very different ways.

### Sveltia CMS: polish the same model

Sveltia CMS keeps Decap's architecture and improves the execution. Same configuration format. Same widget-based editing model. Same browser-based admin. But the UI is cleaner, collections load much faster, i18n is first-class, and hundreds of long-standing Decap issues are fixed. Its editorial workflow (submit for review, approve, publish) works on GitHub, GitLab, and Gitea/Forgejo.

Migration is close to zero effort: swap the script, keep your config. For teams with existing Decap setups, Sveltia is the pragmatic upgrade.

### GitCMS: a different job

GitCMS doesn't start from Decap's architecture. A coding agent runs `create-gitcms` in the repo, detects your collections, and writes the `.gitcms/` configuration; there's no admin page to add. One repository can hold several websites, each configured separately.

Around the files, GitCMS runs a workflow for people who don't use Git: a content board (Ideas, Draft, Review, Published), reviews in the editor with inline comments and approvals, Google sign-in for invited editors, and per-site access. It's a bigger change than moving to Sveltia, and it's aimed at a different reader of the admin.

## The editor gap

Sveltia modernizes Decap's widget-based editor. Fields are cleaner and interactions are smoother, but the model is still form-based: you fill in fields, each mapped to a frontmatter key or the body.

GitCMS gives you a **document-style visual editor**: slash commands, drag-and-drop blocks, tables, callouts, and frontmatter as typed form fields. MDX components and SSG shortcodes are kept intact (beta). Site data like menus and footers in JSON, YAML, or TOML is edited as forms, and only changed values are written back.

For short, structured entries, a form editor can be the more natural fit. For long-form content like blog posts, docs, and guides, a writing-focused editor usually wins.

## AI agents and MCP

Sveltia takes AI seriously on the developer side. It publishes an official agent skill that teaches Claude, Codex, Cursor, and other coding agents to install, configure, migrate, and debug Sveltia CMS, plus `llms.txt` files for its docs. Its docs say it doesn't have its own MCP server yet, and in-editor AI writing is on the roadmap.

GitCMS's agent story is aimed at the content side. ChatGPT, Claude, and other MCP clients connect to GitCMS, read and edit entries and site data, draft inside content tasks, and submit for review. A person publishes. Two beta features close the loop with coding agents: **Change Requests**, where clients pin feedback on the live site and it becomes a GitHub issue that "Copy prompt" hands to Claude Code, Codex, or Cursor, and **preview deployments**, so reviewers see drafts on the real site before publishing.

Sveltia CMS is free, and like Decap, the browser-based model means no hosting cost for the CMS itself. If your budget is zero and Sveltia's editor fits your team, the price can't be beat.

GitCMS is a paid hosted product. You're paying for a different editing experience, the review workflow, and MCP access; see pricing above.

## Where Sveltia CMS is genuinely better

Sveltia CMS is the stronger choice when you're **upgrading from Decap CMS** or when **free and simple matters most**.

- **Drop-in Decap successor.** Keep your config and get a faster, cleaner admin.
- **Free and open source**, with no server to run.
- **More Git hosts.** GitHub, GitLab, and Gitea/Forgejo. GitCMS supports GitHub only.
- **Strong i18n** for multi-language sites.
- **Very active development.** Multiple releases a week through October 2026.

If you like Decap's model and want it done well, Sveltia is the pragmatic choice.

## Where GitCMS is better

GitCMS is better when **the people running the site aren't developers, and some of them are agents**.

- **A writing-focused editor** non-technical editors adopt without training, plus forms for site data
- **Review as the product**: content board, reviews in the editor, preview deployments (beta)
- **Client access**: Google sign-in, per-site access, and Change Requests (beta) on the live site
- **MCP access** so content agents draft for review instead of committing directly
- **Setup by your coding agent**, including several sites in one repository

## Decision by use case

**Upgrading from Decap CMS with minimal effort:** Sveltia CMS is the obvious choice.

**Zero budget, simple content site:** Sveltia CMS is the right answer.

**Multi-language content with strong i18n needs:** Sveltia CMS has an edge.

**Repository on GitLab, Gitea, or Forgejo:** Sveltia CMS is the better fit.

**Agency handing a Claude Code or Astro site to a client:** GitCMS is the better fit.

**AI agents drafting website changes with human review before publishing:** GitCMS is the better fit.
